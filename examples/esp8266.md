# ESP8266 (Xtensa LX106) — Compile and Flash Guide

Step-by-step walkthrough to build and flash the **Hello from KTOS!** demo on any NodeMCU, Wemos D1 Mini, or bare ESP-01.

---

## Prerequisites

| Tool | Version tested | Install |
|------|---------------|---------|
| xtensa-lx106-elf toolchain | GCC 10+ | see §1 |
| ESP8266 Non-OS SDK | 3.0.x | see §2 |
| esptool.py | 4.x | `pip install esptool` |
| Python 3 | 3.8+ | system package manager |

---

## 1 — Install the Xtensa LX106 toolchain

### Linux (Ubuntu / Debian)

> **Note:** `sudo apt update` may print errors about unrelated third-party
> repositories (e.g. MariaDB MaxScale, deadsnakes PPA). These are harmless —
> skip `apt update` and run the install directly if you see them.

```bash
# esp-open-sdk builds the toolchain + SDK in one step
sudo apt install -y make unzip gcc g++ gawk bison flex texinfo gperf libtool automake libncurses-dev python3 python3-pip python3-serial

git clone --recursive https://github.com/pfalcon/esp-open-sdk.git
cd esp-open-sdk
make STANDALONE=y        # takes 15–30 minutes

# Add the toolchain to PATH
echo 'export PATH="$HOME/esp-open-sdk/xtensa-lx106-elf/bin:$PATH"' >> ~/.bashrc
source ~/.bashrc
```

Verify:

```bash
xtensa-lx106-elf-gcc --version
# xtensa-lx106-elf-gcc (crosstool-NG ...) 10.x.x
```

### macOS (Homebrew)

```bash
brew tap esp8266/esp8266
brew install xtensa-lx106-elf-gcc esptool
```

### Windows (WSL2)

Run all steps inside a WSL2 Ubuntu terminal (same as Linux above).  
The serial port will be `/dev/ttyUSBx` or `/dev/ttyACMx` — run `dmesg | tail` after plugging in to find it.

## 2 — Locate the Non-OS SDK

The SDK is built inside `esp-open-sdk/sdk/` when you use esp-open-sdk.  
Check it exists:

```bash
ls ~/esp-open-sdk/sdk/ld/eagle.app.v6.ld
```

If you installed the SDK elsewhere, set `SDK_DIR` when running `make`:

```bash
make SDK_DIR=/path/to/esp8266-sdk
```

---

## 3 — Build the firmware

```bash
cd KTOS/examples/esp8266/hello_ktos

make
```

Expected output:

```
  Build OK:
    hello_ktos-0x00000.bin  (flash at 0x00000)
    hello_ktos-0x10000.bin  (flash at 0x10000)
```

> **Why two binaries?**  
> The ESP8266 Non-OS SDK splits the firmware into a boot-stub (`0x00000`) and
> the main application (`0x10000`).  Both must be flashed.

---

## 4 — Enter flash mode

Put the ESP8266 into bootloader mode **before** running esptool:

| Board | Method |
|-------|--------|
| NodeMCU / Wemos D1 Mini | Hold **FLASH** button, press **RST**, release **FLASH** |
| ESP-01 | Pull GPIO0 LOW, cycle power or pulse RST LOW then HIGH |

---

## 5 — Flash the firmware

Replace `/dev/ttyUSB0` with your actual port:

```bash
make flash PORT=/dev/ttyUSB0
```

Or flash manually:

```bash
esptool.py --port /dev/ttyUSB0 --baud 460800 write_flash \
    --flash_mode dio --flash_size 1MB \
    0x00000 hello_ktos-0x00000.bin \
    0x10000 hello_ktos-0x10000.bin
```

Flash mode and size flags by board:

| Board | `--flash_mode` | `--flash_size` |
|-------|----------------|----------------|
| NodeMCU v2/v3 | `dio` | `4MB` |
| Wemos D1 Mini | `dio` | `4MB` |
| ESP-01 (512 KB) | `dout` | `512KB` |
| ESP-01S (1 MB) | `dout` | `1MB` |

---

## 6 — Open a serial monitor

After flashing, reset the board and open a terminal at **115200 baud, 8N1**:

```bash
# minicom
minicom -D /dev/ttyUSB0 -b 115200

# screen
screen /dev/ttyUSB0 115200

# picocom
picocom -b 115200 /dev/ttyUSB0

# Python one-liner
python3 -c "
import serial, sys
s = serial.Serial('/dev/ttyUSB0', 115200)
while True: sys.stdout.write(s.readline().decode(errors='replace'))
"
```

Expected output (repeats every second):

```
=============================
  KTOS on ESP8266 - running!
=============================
Hello from KTOS!
Hello from KTOS!
Hello from KTOS!
...
```

## How it works

```
ESP8266 ROM boot
    └─> SDK startup (windowed ABI)
           └─> user_init()          [startup.c — windowed ABI]
                  │  registers FRC1 ISR via ETS
                  │  callx0 ──────────────────────────────────────┐
                                                                   ▼
                                               ktos_app_main()  [main.c — CALL0 ABI]
                                                  ktos_InitTask(hello_task, ...)
                                                  ktos_RunOS()
                                                     └─> ktos_hal_StartScheduler()
                                                            └─> hello_task()
                                                                   ├─ prints banner
                                                                   └─ loops every 1 s
```

### ABI boundary (`callx0`)

The ESP8266 ROM calls `user_init()` using the **windowed ABI** (CALL4 instruction,
register window rotation).  All KTOS code is compiled with `-mabi=call0` (no windowing)
for a simple, correct context switch.  The two worlds are bridged by:

```c
// In startup.c (windowed ABI):
__asm__ volatile("callx0 %0" :: "r"(ktos_app_main));
```

`callx0` jumps to a CALL0 function without rotating the register window, so the
stack pointer `a1` carries across correctly.

### Why `-mabi=call0`?

Xtensa's default ABI uses rotating register windows (`ENTRY`/`RETW`).  A context
switch must save **all live windows** before swapping stack pointers — dozens of
registers per window, with spill/fill exception handlers.  CALL0 eliminates
windowing: `a0-a15` are always the same physical registers, making the context
switch a straightforward 64-byte frame save/restore.  See
`bsp/esp8266/ktos_bsp.c` for the full implementation.

## File overview

| File | ABI | Purpose |
|------|-----|---------|
| `startup.c` | windowed | `user_init()` entry point, FRC1 ISR shim |
| `main.c` | CALL0 | Task definition, UART driver, `ktos_app_main()` |
| `alloc.c` | CALL0 | Bump allocator replacing SDK `malloc`/`calloc` |
| `Makefile` | — | Two-ABI build rules |
| `bsp/esp8266/ktos_bsp.c` | CALL0 | HAL: interrupts, FRC1 timer, context switch |

## Troubleshooting

| Symptom | Likely cause | Fix |
|---------|-------------|-----|
| `esptool: Could not connect` | Board not in flash mode | Re-enter bootloader (§4) |
| Garbled output | Wrong baud rate | Set monitor to exactly **115200** |
| No output at all | Wrong flash addresses | Check board flash size; use `--flash_size detect` |
| Linker errors about `malloc` | Wrong SDK path | Set `SDK_DIR=` correctly |
| `xtensa-lx106-elf-gcc: not found` | Toolchain not in PATH | Re-run `source ~/.bashrc` |
| Board crashes / watchdog reset | Stack too small | Increase `TASK_MAIN_STACK_SIZE` in `main.c` |

## Next steps

- **Two tasks**: add a second `ktos_InitTask()` call.  Once the multi-task
  cooperative switch is fully wired (see `core/ktos.c` — `ktos_SwitchTask`),
  each task can `return 1000` to yield for 1 s and let the other run.
- **WiFi**: the WiFi stack requires windowed ABI.  Integrate it by keeping all
  SDK/WiFi calls inside `startup.c` (windowed) and bridging results to KTOS
  tasks via `ktos_SendMsg()`.
- **Custom baud rate**: change `UART_BAUD_DIV` in `main.c`
  (`div = 80 000 000 / baud`).
